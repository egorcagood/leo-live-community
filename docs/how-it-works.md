# Как устроена первая версия

Community - самостоятельное приложение. Для локальных показаний сервер не нужен. В приложении нет поля API-ключа, регистрации или скрытого адреса сервера.

```text
Автомобиль → OBD-адаптер → Bluetooth LE → Android
                                        ├─ экран показаний
                                        └─ частный журнал → CSV по кнопке

Вымышленный автомобиль → demo → тот же экран, журнал с меткой DEMO
```

## Настоящие показания

Пользователь выбирает BLE-устройство и подтверждает, что автомобиль припаркован. Приложение проверяет GATT-профиль: сервис `18f0`, запись `2af1`, уведомления `2af0`. Это конкретный профиль; совпадение имени адаптера само по себе ничего не доказывает.

Затем идут фиксированные команды настройки адаптера: `ATZ`, `ATE0`, `ATL0`, `ATS0`, `ATH0`, `ATSP0`. Они управляют адаптером, а не перепрограммируют автомобиль. После `0100` приложение читает карты поддержки следующих страниц до `0140`, только если предыдущая карта объявила продолжение. Само наличие OBD-разъёма не означает поддержку каждого показателя.

Поддерживаемые показатели опрашиваются по очереди. Не более одного запроса одновременно; обычный опрос - примерно один запрос в секунду. При семи доступных показателях каждый обновится примерно раз в семь секунд, а не каждую секунду. Скорость ответа ЭБУ может увеличить интервал. Если замеру больше 15 секунд, экран ожидает новый замер. После отключения текущие числа очищаются.

Кнопка ошибок отдельно читает стандартные режимы `03` и `07`. Она не стирает ошибки. Нет кнопки ввода произвольной команды, команд кодирования или тестов исполнительных механизмов. Запросы SRS, ABS, коробки и специфичные команды производителя в этот выпуск не входят.

## Где находятся ограничения

- `core/ReadPolicy.java` - точный список разрешённых команд, повторно проверяемый непосредственно перед BLE-записью.
- `core/RequestQueue.java` - один запрос в полёте, максимум 16 ожидающих, ответ до 4096 символов, ожидание до 10 секунд. Тайм-аут, лишний ответ или переполнение прекращают сеанс. Автоматических повторов и переподключений нет.
- `core/ObdCodec.java` - проверка формата, ожидаемого PID/сервиса и размера. Несовпадающие числовые ответы нескольких ЭБУ не превращаются в одно выдуманное число.
- `BleConnection.java` - один владелец соединения и поколение callback; ответ старого подключения не принимается в новое.
- `MainActivity.java` - выбор источника, разрешения, состояние экрана и остановка при сворачивании.

Парсер поддерживает ограниченные ответы ELM без заголовков. Неизвестное форматирование, в том числе некоторые многострочные/многокадровые ответы, может быть отклонено. Это повод добавить проверенный формат с тестами, а не считать, что ошибок нет.

## Журнал

В частном хранилище приложения сохраняется последняя сессия, максимум 10 000 строк. Новый сеанс заменяет предыдущий. В памяти и при медленном диске очередь сохранений ограничена: остаётся только последний ожидающий снимок. При аварийном завершении могут потеряться последние строки после последнего сохранения.

CSV содержит `timestamp_ms,source,field,value,unit,status`. Время - часы телефона; `source` - `DEMO` либо `OBD`. Демо всегда синтетическое. Недоступное значение записывается пустым с `UNAVAILABLE`, а не нулём. Единицы: `rpm`, `km/h`, `C`, `%`, `V`; коды DTC разделены точкой с запятой.

VIN, координаты, разговоры и адрес Bluetooth в журнал не записываются. Экспорт открывает системный выбор файла; выбранный пользователем облачный диск сам может синхронизировать этот файл. Автоматическая резервная копия Android отключена.

Экспорт, блокировка и переход в другое приложение останавливают измерения. Продолжение требует нового ручного подключения. Фоновая запись - отдельная будущая работа, не скрытая настройка.
